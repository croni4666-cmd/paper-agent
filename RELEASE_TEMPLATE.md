# paper-agent Release Notes Template

> **Purpose**: Standard format for `paper-agent` GitHub releases.
> v3.9.20.0 was the first release to use this template (refactored from
> the original changelog-style format after user feedback that the
> formatting "isn't pretty enough").

## Why this template

Patterns adopted from widely-respected release notes:
- **[astral-sh/ruff](https://github.com/astral-sh/ruff/releases)** — categorized
  sections with rule codes, Install/Download blocks, Contributors
- **[astral-sh/uv](https://github.com/astral-sh/uv/releases)** — same
- **[huggingface/transformers](https://github.com/huggingface/transformers/releases)** —
  hero header + TL;DR + categorized sections + breaking-changes callout
- **[withastro/astro](https://github.com/withastro/astro/releases)** —
  thanks-to-contributor inline

Key design choices for `paper-agent`:
- ⚡ **TL;DR at top** for 5-second scan
- ⬆️ **Upgrade section early** so users can act immediately
- 📊 **Visual emoji hierarchy** so the eye finds sections fast
- 🧪 **Tests table** because paper-agent cares about correctness
- 🔄 **`Full Changelog` link** at the bottom (auto-generated by GitHub)

## Section rules

### Hero
- `🚀` rocket emoji
- Bold **one-line tagline** (≤ 80 chars)
- Blockquote metadata line: 📅 date · 🏷️ bump type · 📦 files · ➕ lines · ✅ tests
- **Skip metadata line for very small PATCH releases** (< 5 files, < 100 lines)

### TL;DR
- 3–5 bullets, **always present**
- Use these emoji markers consistently:
  - `✨` New feature
  - `🔧` Improvement
  - `🐛` Bug fix
  - `📚` Documentation
  - `⚠️` Breaking change
  - `🚀` Performance
  - `🧪` Test
  - `📦` Dependency
- Each bullet: emoji + **bold feature name** + `—` + one-line description

### Upgrade
- Always a code block, always 2 lines: `pip install --upgrade` + `pa version`
- Skip if the release doesn't change `pa` itself (e.g., docs-only)

### What's New
- Numbered subsections, `### N. <emoji> <title> · [<roadmap-id>]`
- Each subsection:
  - 1-paragraph description
  - Code block with example (output, not just command)
  - Optional: small data table (use when output is naturally tabular)
  - Optional: mermaid block for visual diagrams (PRISMA, flow, etc.)
  - Optional: "How it works" / "Why it matters" closing

### Tests
- Markdown table, files × new count × status
- **Total new** row
- Below table: regression check + grand total
- Always include the pre-existing `test_mcp_setup` fail with a note
  that it's unrelated

### Files Changed
- Markdown table, files × status × delta
- Status: `**NEW**`, `modified`, `bump`, `docs`, `tests`
- Delta: KB for new files, LOC for modifications, version for version bumps
- Below table: "No new external dependencies" (or list them)

### Links
- 4 main docs: CHANGELOG, ROADMAP, README, previous release
- **Full Changelog** link: `compare/vX.Y.Z-1...vX.Y.Z`

### License footer
- Always present, `<sub>` for small text
- License + use case

## Migration from old format

Old format (v3.9.20.0 before this template):
- 7963 chars, no TL;DR, no install section, no emoji hierarchy
- Numbered "What's in this release" instead of categorized
- Tests / Files / ROADMAP status as flat bullet lists

New format (v3.9.20.0 after this template):
- 5891 chars (~25% shorter)
- TL;DR with 4 emoji bullets at top
- Install section near the top
- Categorized "What's New" with one emoji per subsection
- Tests + Files as markdown tables
- License footer
