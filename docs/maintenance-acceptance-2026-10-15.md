## 发现与修复

| 问题 | 补强与行为 |
| --- | --- |
| HTTP 429/503、断网等被部分引擎返回为空列表 | Crossref、OpenAlex、Semantic Scholar、PubMed、ClinicalTrials 检查状态码和必要响应结构；失败显示为引擎错误，真正的空结果仍成功 |
| 工作进程把非列表结果转换为空列表，坏记录可影响其他来源 | 在工作进程和汇总边界验证行结构、文本及排序字段；隔离异常来源，其他来源继续 |
| PubMed 摘要分块与 arXiv 迭代中断可丢失完成度信息 | 保留已取得的记录，并保留错误行；年份筛选不抹去错误；单个失败引擎仍有结果时，运行报告判为部分完成 |
| 未知引擎和未配置的可选引擎缺少解释 | 未知引擎显示错误；可选跳过使用 `skipped_engines`，重复引擎只执行一次 |
| 可选元数据补全的坏响应可能破坏已有结果 | 隔离补全异常，保留原搜索结果，不标记补全成功 |
| HTTP 响应在异常路径可能未关闭；S2 最后一次失败仍等待退避 | GET、POST、HTTP 错误均关闭响应；重试耗尽后停止额外等待；保留已有进程截止时间与终止机制 |
| 空或格式错误 Cookie 仍可能使 CNKI 显示就绪 | 验证本地配置形状、非空内容和文件时间；空配置不启用。允许 5 秒文件时间精度偏差，显著未来时间不视为新鲜；明确未核验服务登录状态 |

旧提交 `49a8966` 的隔离函数探针确认：429 时三个引擎返回 `[]`，工作进程也把字典返回值改为 `[]`。
压力复测发现 Windows 新文件时间戳存在细小向前偏差，已加入容差及正反例。
巡检器初版把 Crossref 的合法无标题 DOI 记录误报为结构变化，已用仅字段类型检查确认并修正；
缺少可选标题不等于接口失效。

  每轮包括 8 个真实进程竞争同一额度上限、重复提交幂等、3,000 条 Unicode RIS 导出、
  8,000 条成功/超时混合状态汇总、20 份共 80 页生成 PDF 的索引与片段处理，
  以及坏响应、限流、超时、非法进程返回、部分完成和连接清理检查。
- 既有一致性门：190 项测试与 18 个子测试通过；十轮压力复测，每轮另外运行 19 项边界检查和
  74 项网关/存储检查。这里的重复次数用于暴露工程竞态，不是独立科学样本。
- doctor、RIS、运行报告回归：39 项，Windows 上 38 项通过、1 项 POSIX FIFO 检查留给 Linux CI。
- CI 在 Windows/Linux 与 Python 3.10–3.12 上执行三轮能力压力门；另保留完整回归和独立安装包检查。
  在线接口巡检不进入强制 CI，避免将限流或本地网络波动误判为代码回归。

复现命令（需要项目测试依赖）：

```console
python tools/capability_stress_gate.py --rounds 5
python tools/consistency_quality_gate.py --stress-runs 10
python tools/engine_health.py

```

压力门禁止网络并只使用生成样例。`engine_health` 默认不联网，状态是 `not_checked`；
只有 `--live` 才对所选公开引擎各发一次无密钥请求，无重试。
单引擎子进程限时 15 秒、响应上限 2 MiB，不继承代理凭据，不加载 dotenv、Cookie 或 SDK，
不保存响应正文、论文记录或 PDF。退出码 0 的在线巡检要求所有已选引擎均为 `healthy`；
空结果、限流、无法访问或结构变化均非零，未选引擎明确列出。
该脚本检验公开接口形状与访问状态，不替代 SDK/登录/下载全链路验收。

## 维护阶段

当前聊天采用每周一北京时间 10:00 的轻量巡检安排：

1. 检查工作区状态和当前提交，不覆盖用户改动；先运行离线引擎契约及能力门。
2. 对六个公开接口各做一次无密钥探测，比较上次状态；不收集语料、不下载 PDF、不读取凭据。
3. 保存有限状态与耗时，正常且无变化时保持安静。新故障、结构变动、恢复或需要决策时通知；
   相同未变故障不每周重复轰炸。
4. 针对确认的代码回归准备最小修复；遵守全部十项当前提交 CI 的质量门。
   不自动升级主版本依赖、引入付费/托管服务、恢复语料工作或添加功能。

该安排由桌面应用的计划任务承接，仓库自身不启动守护进程或定时器。
执行本地任务时机器、应用与项目需可用，见
[官方计划任务说明](https://learn.chatgpt.com/docs/automations?surface=app)。
如果运行、权限或网络失败，保留失败/未知状态，不能登记为健康完成。

维护阶段的重新开发条件：确认的数据丢失/超限授权/错误成功回归、持续接口结构变化、
明确的兼容性或依赖安全修复需求，或用户提出新的实际需求。
其余已搁置事项继续保留边界；没有语料或人工核验就不宣布学术能力提升。
