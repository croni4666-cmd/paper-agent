But 4 packaging inconsistencies in the v3.9.25.0 release artifacts:

Issue 1: SKILL.md frontmatter had stale version fields
  - version: 3.9.24.0 (should be 3.9.25.0)
  - pa_cli_version: 3.9.23.0 (should be 3.9.25.0)
  Fix: bumped to 3.9.25.0; this PATCH bumps to 3.9.25.1.

Issue 2: SKILL.md description had a 15-line duplicated v3.9.23.0 block
  - Started with broken text ").rch for academic papers by" (concat artifact)
  - Listed "7 engines" (we have 8 since v3.9.12.0)
  Fix: removed the duplicate, kept the new 8-engine description.

Issue 3: SKILL.md `### scripts/search.py — Search 7 engines` heading
  was leftover from v3.9.23.0
  Fix: changed to "Search 8 engines (v3.9.22.0+)".

Issue 4: scripts/version.py hardcoded "skill_version": "3.9.23.0"
  Fix: bumped to 3.9.25.0; this PATCH bumps to 3.9.25.1.

Issue 5: Chinese text mojibake in 6 .py docstrings + 1 SKILL.md line
  - Root cause: UTF-8 → cp1252 → UTF-8 round-trip on em-dash "—" (U+2014)
  - Symptom: "鈥?" (bytes E9 88 A5 3F) instead of "—"
  - Affects SKILL.md L32 and docstrings in search/fetch/fetch_batch/
    review/citations/keys/cache/version.py
  Fix: replaced all 鈥? sequences with "—", stripped UTF-8 BOM from
  7 .py files (U+FEFF at start), fixed search.py L14 example
  (Chinese chars "数字普惠金融 家庭消费" was rendered as mojibake by
  earlier Edit tool calls).

Issue 6 (related): search.py L14 example "数字普惠金融 家庭消费"
  was encoded as mojibake "鏁板瓧鏅儬閲戣瀺 瀹跺涵娑堣垂"
  Fix: re-wrote L14 with proper UTF-8 (also fixed by the mojibake
  cleanup script).
