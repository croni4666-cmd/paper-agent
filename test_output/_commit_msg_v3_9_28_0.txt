- ❌ Relative paths failed: 'refs.bib' looked up under pa_root

User quote: "传入的路径保持相对形式，但子进程在第 98 行切换了工作目录"

Root cause: The wrapper's subprocess.run(cmd, cwd=str(pa_root)) changes
the subprocess CWD to the pa_cli repo dir. Any relative path
(e.g. 'refs.bib') passed via args.bibtex was resolved against pa_root,
not the user's invocation CWD. So 'refs.bib' (which exists in user's
working dir) was looked up under pa_root and not found.

Fix: Resolve user-provided paths to absolute via Path(...).resolve()
BEFORE constructing the subprocess cmd. Path.cwd() is the user's
invocation CWD, so relative paths get resolved against THAT, not pa_root.

  # v3.9.28.0
  args.bibtex = str(Path(args.bibtex).resolve())
  args.output_dir = str(Path(args.output_dir).resolve())
  if args.report:
      args.report = str(Path(args.report).resolve())
  if args.summary_json:
      args.summary_json = str(Path(args.summary_json).resolve())

This happens RIGHT after parse_args() and BEFORE the
subprocess.run(cmd, cwd=str(pa_root)) call, so the absolute paths
survive the CWD change.

Discovered during debugging:
  When using subprocess.run with a custom cwd, ALL paths in cmd list
  are interpreted relative to that cwd, not the parent's cwd. This is
  standard POSIX behavior, but easy to forget. The fix is to always
  resolve paths to absolute BEFORE constructing the cmd list. This
  applies to all wrappers (search.py, fetch.py, etc.) — they should
  also pre-resolve their input paths for the same reason.
