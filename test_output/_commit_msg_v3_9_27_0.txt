fix(fetch-batch): v3.9.27.0 — Skill wrapper entry + size fallback (2 v3.9.26.0 leftovers)

User tested v3.9.26.0 with `pa fetch-batch` on 2 Wilson disease DOIs
(53.7s, 1.19MB total). 2 of 4 bugs were fixed in v3.9.26.0 (`n_skipped`
counter, `--clean-xml` flag). 2 issues remained:

Issue 1: Skill wrapper still failed with "No such option '--out-dir'"

  Root cause: The Skill's `scripts/fetch_batch.py` was calling
  `python -m pa_cli.cli fetch-batch`. The `pa_cli.cli` path is the
  internal subpackage module — when invoked via `-m`, it loads
  `pa_cli/cli.py` directly. But the user's installed environment
  loaded a STALE/CACHED `pa_cli/cli.py` (containing the OLD
  `fetch_batch()` CNKI guide function that has no `--out-dir` option).
  The OLD function won the Click registration race in v3.9.26.0.

  Fix: Use the documented package entry point instead:
    # Before (v3.9.26.0):
    PYTHON, "-m", "pa_cli.cli", "fetch-batch", ...
    # After (v3.9.27.0):
    PYTHON, "-m", "pa_cli", "fetch-batch", ...

  `python -m pa_cli` routes through `pa_cli/__main__.py` which does
  `from .cli import main`. This is the documented entry point in
  `pyproject.toml` (`[project.scripts]`) and always uses the live
  editable-install code.

Issue 2: PMC jats_pdf `size_bytes` still = 0 in summary

  Root cause: The v3.9.26.0 fix used `r.get('size_bytes', 0)` to read
  the fetch result. But the PMC jats_pdf channel (v3.9.21.0) returns
  `{"size": N}` (NOT `size_bytes`). Inner functions in pa_cli/fetch.py:
    - L247: _pmc_europe_pdf returns "size": len(body)
    - L330, L404: same pattern
    - L482: _pmc_jats_to_pdf returns "size": len(pdf_bytes)
    - L558, L585: fetch_pmc_doi reads jats_result.get("size")

  So when the wrapper called fetch() for a PMC paper, the result dict
  has `size` (not `size_bytes`), and `r.get('size_bytes', 0)` returned 0.

  Fix: Use a fallback chain in pa_cli/fetch_batch.py:
    # v3.9.27.0: try size_bytes → size → stat(file)
    result.size_bytes = (
        r.get("size_bytes")
        or r.get("size")
        or (Path(r.get("path", str(out_path))).stat().st_size
            if Path(r.get("path", str(out_path))).exists()
            else 0)
    )

  This works for ALL channels regardless of which key they return. The
  file-stat fallback is guarded by `if Path(...).exists()` to avoid
  FileNotFoundError for failed fetches.

Discovered during debugging:
  When the same Python module can be loaded via two different paths
  (e.g. `pa_cli.cli` vs `pa_cli`), Python may load DIFFERENT versions
  depending on sys.path order. `python -m pa_cli.cli` loads the cli.py
  module directly, while `python -m pa_cli` loads pa_cli/__main__.py
  which then does `from .cli import main`. The latter goes through
  the package's __init__.py first (setting up __version__ etc), while
  the former can bypass it.

  In editable installs (`pip install -e .`), the package is registered
  with setuptools' finder. `pa_cli` (package) and `pa_cli.cli`
  (subpackage) are both importable. For entry points, always use
  the package (`-m pa_cli`) not the subpackage (`-m pa_cli.cli`)
  to ensure consistent loading.
